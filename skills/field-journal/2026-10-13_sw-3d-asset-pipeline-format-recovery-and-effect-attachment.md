## 完整执行链路

1. **"渲染不对"先拆层定位,不猜**:同一 GLB 并排渲染「原始顶点 / 绑定姿势 / 动画帧」三联图 → 网格与蒙皮正确,问题只在 UV。把 UV 线框叠到贴图上,与「V 翻转」变体并排 → 翻转版岛屿 100% 对齐。根因:解析器已做 `v = 1 - v`,导出器又翻一次(两次翻转抵消)。
2. **查看器自身 bug 与数据 bug 分开**:SkinnedMesh 在首帧渲染前 `boneMatrices` 全 0 → `Box3.setFromObject` 塌缩成点 → 自动缩放 1.6x 巨大化。另:部分模型把技能专用部件**停放在 -1000 游戏单位**(≈ -64000 网格单位),ROBO 有 79% 顶点在那里;"按中位数取景"会对准停放堆 → 改为"按原点附近顶点取景"。
3. **分类用游戏自己的标志位**:单位表 `collection view`(图鉴可见)= 可玩;`boss`;`homunculus`/`collabo`。必须**只接受与表头等宽的行**——同一文件里 60 列的皮肤表行会被当成怪物(241 个"联动"假阳性)。`awaken = -1`(불완의/"不完全")是副本敌人变体,会覆盖正常形态标签。
4. **多模型怪物**:`change` 列 = 技能变身单位(德鲁伊兽形);`add model` 列 = 召唤物;`dat name` 第二项 = 伴随模型(`*_sub.dat`);同一形态多个 dat(按元素区分的模型)会互相覆盖目录 → 加元素后缀。
5. **数据源"边界"要量**:Steam `Base_Contents.bundle` 与 APK 安装期资源包 `split_asset_base.apk` **逐字节一致**(25,316 文件 / 502 模型);新手教程单位只在 Steam `Base_Tutorial.bundle`;模拟器下载目录 = **补丁层**(86 个基础模型被重制版覆盖,如 Dragon 0.48 MB → 2.4 MB)⇒ 优先级必须是「下载层 → Steam 底层」,且**源优先级要压过文件名拼写变体**(`(unit)_` / `unit_mdl_`)。
6. **adb 增量拉取**:`find -exec stat -c '%s %Y %n'` 列清单 → 按 size+mtime 比对 → 批量写清单到设备临时文件 → `adb exec-out "tar -cf - -T list"` 流式解包(Python `tarfile` + `filter="data"` 防路径穿越)。217 个模型 12 秒。`localvalue.dat` 在私有目录,需 root adb(MuMu 自带)。
7. **PLM 骨骼新版本**:`PLM%` 及以后版本,骨骼前的块是 0x11 字节(旧代码只对 `%` 用 0x11,其余回落 0x08)。`PLM'`~`PLM0` 改为 float32;平移单位是 16.16 定点:`× 65536 / scale_divider`。**验收方式**:用候选系数重建骨骼世界坐标,与"绑定到该骨骼的顶点质心"求中位距离,k=64 时残差与已知正确的整数格式模型**同量级**(2.8~6.5 vs 3.9~6.9)。
8. **PEFT 特效格式(1.9 万文件)**:按"自带冗余"逐层收敛——trailer 重复计数一致 → 存储的包围盒 == 解码坐标的精确 min/max → 时间轴位掩码 set-bit 数 × 顶点数 == 坐标池大小、alpha 掩码 set-bit 数 == alpha 字节数。剩余失败用"哪一位能解释全部失败样本"定位出 `0x0800` = 记录带 alpha 轨。最终 19,062/19,168(99.4%)全约束通过。
9. **特效挂点**:表里的"骨骼号"有两种语义——挂载模式 3 = 真实 bone id;模式 0/1 = **dummy 编号**(骨骼 `flag != 0xFF` 时 flag 即 dummy 号),0 = 模型原点(地面),**不是** bone 0(bone 0 常在髋部高度,导致特效整体上浮 61 单位)。layer 1/2 = 朝相机 / 绕 Y 轴的公告板。最后用用户提供的游戏内截图对照确认。
